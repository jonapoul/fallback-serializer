# Fallback Serializer

A Kotlin compiler plugin for enums being serialized using [kotlinx.serialization](https://github.com/Kotlin/kotlinx.serialization). Unknown strings decode to a fallback entry instead of throwing SerializationException, which helps compatibility if your server returns new enum values before your client has been updated to support them. This allows your apps to more gracefully handle unsupported response values.

## Setup

```kotlin
plugins {
  kotlin("multiplatform") // or kotlin("jvm"), kotlin("android")
  kotlin("plugin.serialization")
  id("dev.jonpoulton.fallback-serializer") version "<version>"
}
```

The Gradle plugin adds the `runtime` dependency for you.

## Usage

```kotlin
@Serializable(with = Fruit.FallbackSerializer::class)
enum class Fruit {
  Apple,
  @SerialName("cherry") Cherry,
  @Fallback Unknown,
}

Json.decodeFromString<Fruit>("\"Apple\"") // -> Fruit.Apple
Json.decodeFromString<Fruit>("\"cherry\"") // -> Fruit.Cherry
Json.decodeFromString<Fruit>("\"Orange\"") // -> Fruit.Unknown
```

The `FallbackSerializer` is generated by the compiler plugin to handle the fallback behaviour of the single `@Fallback`-annotated entry. If you try to leave a standard `@Serializable` annotation on your enum class (or no `Serializable` at all), the compiler will fail the build to let you know.

Any error while decoding the value gives the fallback entry, not only unknown strings. For example, with Json an empty
input or a `JsonNull` element decodes to `Fruit.Unknown`, and a number or object gives a less helpful error than usual.

With `Json { coerceInputValues = true }`, an unknown value for a property with a default gives that default instead of
the fallback entry. Json replaces the value before the serializer runs. Properties without a default still get the
fallback entry.
